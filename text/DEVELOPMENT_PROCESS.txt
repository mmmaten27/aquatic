================================================================================
ขั้นตอนที่ 1 — เชื่อมต่อเซ็นเซอร์และจัดเก็บข้อมูล
================================================================================

จุดเริ่มต้นของโปรเจกต์คือการทำให้ระบบ "มีข้อมูลจริง" ก่อนสิ่งอื่นใด

เซ็นเซอร์แต่ละตัวในบ่อเลี้ยงปลา (pH, อุณหภูมิ, ออกซิเจน, แอมโมเนีย,
ความขุ่น, ค่านำไฟฟ้า) ถูกเชื่อมต่อผ่าน IoT Sensor Node
ซึ่งทำหน้าที่อ่านค่าและเขียนลงฐานข้อมูล MySQL โดยอัตโนมัติทุก N วินาที

เหตุผลที่เริ่มจากส่วนนี้ก่อน:
→ ระบบตรวจสอบเซ็นเซอร์ต้องการข้อมูลสะสมในระยะเวลาหนึ่ง
→ ขณะพัฒนาส่วนอื่น ข้อมูลจะถูกบันทึกอยู่เบื้องหลังโดยอัตโนมัติ
→ เมื่อทดสอบกราฟจะมีข้อมูลจริงพร้อมใช้งานทันที

================================================================================
ขั้นตอนที่ 2 — ออกแบบโครงสร้างระบบและฐานข้อมูล
================================================================================

ก่อนเขียนโค้ดส่วนหลัก ทำการวางแผนภาพรวมทั้งหมด:

  ด้านฐานข้อมูล:
  - กำหนดว่าต้องการเก็บข้อมูลอะไรบ้าง
  - ออกแบบตารางให้ตอบโจทย์การใช้งาน 2 ด้าน
    (ระบบ Access Control และระบบเซ็นเซอร์บ่อปลา)
  - กำหนดความสัมพันธ์ระหว่างตาราง

  ด้านสถาปัตยกรรมเว็บ:
  - เลือกใช้ Python Flask เป็น Backend
  - ออกแบบ REST API Endpoint สำหรับแต่ละ feature
  - กำหนดหน้าเว็บที่จำเป็น (Dashboard, Personnel, History, Tank)

  ด้านระบบกล้อง:
  - กำหนดตำแหน่งและหน้าที่ของกล้องแต่ละตัว
  - วางแผน Thread architecture (กล้องแต่ละตัวทำงานแยก Thread)

================================================================================
ขั้นตอนที่ 3 — พัฒนาส่วนแสดงผลเซ็นเซอร์
================================================================================

เริ่มพัฒนาหน้าเว็บส่วนแสดงค่าเซ็นเซอร์ก่อน เพราะ:
→ ต้องการเห็นข้อมูลจริงบนหน้าเว็บโดยเร็ว
→ ส่วนนี้ซับซ้อนน้อยกว่า AI ทำให้เป็นฐานที่ดีก่อนพัฒนาส่วนยาก

สิ่งที่พัฒนาในขั้นตอนนี้:
  - Dashboard หลัก: แสดงค่าเซ็นเซอร์ 3 ค่า (pH, อุณหภูมิ, DO) แบบ Real-time
  - กราฟประวัติ: เลือกดูข้อมูลย้อนหลัง 1/6/24 ชั่วโมง
  - ระบบ Alert: ตรวจสอบว่าค่าเกินเกณฑ์หรือไม่ แจ้งเตือน Telegram
  - Fault Detection: ตรวจจับเซ็นเซอร์ที่ส่งค่า 0 ต่อเนื่อง
  - Trend Analysis: วิเคราะห์แนวโน้มว่าค่ากำลังจะเกินเกณฑ์เมื่อไหร่
  - ระบบ Login/Register: ป้องกันการเข้าถึงโดยไม่ได้รับอนุญาต

================================================================================
ขั้นตอนที่ 4 — พัฒนาระบบ AI ตรวจจับบุคคล
================================================================================

ส่วนที่ซับซ้อนที่สุดของโปรเจกต์ พัฒนาแบบ Layer by Layer:

  Layer 1 — Person Detection (YOLOv8)
  ติดตั้งกล้อง 4 ตัว เขียน Multi-thread ให้แต่ละกล้องทำงานแยกกัน
  ใช้ YOLOv8n ตรวจจับว่ามีคนอยู่ในเฟรมหรือไม่

  Layer 2 — Face Recognition (InsightFace ArcFace)
  เพิ่มระบบจดจำใบหน้าเข้าไป โดยลงทะเบียนสมาชิกพร้อมรูปภาพ
  ระบบแปลงรูปเป็น embedding vector แล้วเปรียบเทียบ cosine distance

  Layer 3 — Access Control State Machine
  ออกแบบ Logic การตัดสินใจ ENTER/EXIT
  กำหนดเงื่อนไขว่ากล้องตัวไหนต้องเห็นอะไร ในเวลาเท่าไหร่
  จึงจะถือว่าคนเข้าหรือออกห้อง

  Layer 4 — Notification & Logging
  เชื่อมต่อ Telegram Bot สำหรับแจ้งเตือนทุกประเภท
  บันทึกเหตุการณ์ลงฐานข้อมูลและไฟล์ log

  Layer 5 — Personnel Management UI
  พัฒนาหน้าจัดการสมาชิก พร้อมระบบถ่ายรูปผ่านกล้องจริง
  มี Pose Guide ช่วยให้ถ่ายรูปได้ถูกมุม 5 ท่า

================================================================================
ขั้นตอนที่ 5 — ทดสอบ ปรับปรุง และพัฒนาต่อเนื่อง
================================================================================

หลังจากระบบทำงานได้เบื้องต้น เข้าสู่รอบของการทดสอบจริง

  ปัญหาที่พบและแก้ไข:

  ปัญหาด้านกล้อง:
  - Camera backend ไม่รองรับ (เปลี่ยนจาก DirectShow → MSMF)
  - กล้องหลุดพร้อมกันจาก USB power ไม่พอ
    → เพิ่ม reconnect logic พร้อม delay ให้ driver ฟื้นตัว

  ปัญหาด้าน Face Recognition:
  - รูปฝึกถ่ายจากโทรศัพท์ → มุมไม่ตรงกับกล้องจริง
    → ถ่ายรูปใหม่จากกล้อง surveillance ครบ 5 ท่า
  - ระบบจำคนผิดบ่อย → ปรับ similarity threshold ให้เข้มขึ้น
  - คนแปลกหน้าไม่ถูก detect เป็น UNKNOWN
    → แก้ logic ให้ตรวจสอบ UNKNOWN แบบ Independent

  ปัญหาด้าน State Machine:
  - EXIT fire ผิดทุก 1-2 นาที → แก้ grace period logic
  - State ค้างหลัง server restart → เพิ่มปุ่ม Reset บน Dashboard
  - Multi-person tracking สับสน → แก้ rate-limit ให้เป็น per-track

  การปรับปรุงที่ต่อเนื่อง:
  - เพิ่มระบบ Log ไฟล์ (system_events.log) เพื่อวิเคราะห์ปัญหา
  - ปรับ confidence threshold ตามผลการทดสอบจริง
  - เปลี่ยนข้อความแจ้งเตือนทั้งหมดเป็นภาษาจีนตัวเต็ม
  - เพิ่ม Pose Guide 5 ท่าในหน้าลงทะเบียนสมาชิก
