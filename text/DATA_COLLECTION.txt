================================================================================
ภาพรวม — ทำไมต้องเก็บข้อมูลก่อน
================================================================================

ระบบจดจำใบหน้าแบบ ArcFace ไม่ใช่ระบบที่ "เรียนรู้จากศูนย์"
แต่ใช้โมเดลที่ผ่านการ Pre-train จากชุดข้อมูลขนาดใหญ่มาแล้ว
(InsightFace buffalo_l ฝึกจากภาพใบหน้ากว่า 1 ล้านรูป)

สิ่งที่เราต้องเก็บข้อมูลเองคือ "ตัวตนเฉพาะของสมาชิกแต่ละคน"
เพื่อให้ระบบรู้ว่า "Tongen หน้าตาเป็นแบบนี้" และ "jiabao หน้าตาเป็นแบบนี้"

กระบวนการนี้เรียกว่า Face Enrollment (การลงทะเบียนใบหน้า)

================================================================================
ส่วนที่ 1 — ข้อมูลที่ต้องเก็บคืออะไร
================================================================================

สิ่งที่เก็บ: ภาพใบหน้าของสมาชิกแต่ละคน จากมุมมองต่างๆ

  เหตุผลที่ต้องหลายมุม:
  ในชีวิตจริง คนไม่ได้หันหน้าตรงให้กล้องเสมอ
  บางครั้งเดินผ่าน บางครั้งเอียงหัว บางครั้งก้มหรือเงย
  ถ้าฝึกด้วยรูปหน้าตรงอย่างเดียว → ระบบจำได้เฉพาะตอนหน้าตรง
  → ในสถานการณ์จริงจะ fail บ่อย

  ท่าที่เก็บ (5 ท่า):
  ┌───────────┬───────────────────────────────────────────┐
  │ ท่า       │ เหตุผล                                    │
  ├───────────┼───────────────────────────────────────────┤
  │ หน้าตรง   │ baseline ที่สำคัญที่สุด                    │
  │ เอียงซ้าย │ จำลองการเดินผ่านกล้องจากทิศซ้าย          │
  │ เอียงขวา  │ จำลองการเดินผ่านกล้องจากทิศขวา           │
  │ ก้มเล็กน้อย│ จำลองการมองลงขณะเดิน                    │
  │ เงยเล็กน้อย│ จำลองการมองขึ้นหรือกล้องอยู่สูง          │
  └───────────┴───────────────────────────────────────────┘

================================================================================
ส่วนที่ 2 — ทำไมต้องถ่ายจากกล้อง Surveillance จริง
================================================================================

นี่คือบทเรียนสำคัญที่ค้นพบระหว่างการพัฒนา

  ปัญหาที่เกิดขึ้นเมื่อใช้รูปจากโทรศัพท์:

  รูปจากโทรศัพท์            รูปจากกล้อง Surveillance
  ──────────────────────────────────────────────────
  ระยะใกล้ ≈ 30-50 ซม.      ระยะไกล ≈ 1-3 เมตร
  แสงสว่างเพียงพอ            แสงห้องปกติ อาจสลัว
  มุมระดับตา                มุมสูง หรือด้านข้าง
  ความละเอียดสูง             ความละเอียดปานกลาง

  ผลที่เกิดขึ้น:
  เมื่อระบบเปรียบเทียบรูปจากโทรศัพท์กับภาพจากกล้องจริง
  Embedding Vector มีความแตกต่างกันมาก
  → ค่า confidence ต่ำ (0.42-0.51) ต่ำกว่า threshold
  → ระบบจำไม่ได้ หรือจำผิดคน

  แนวทางแก้ไข:
  ถ่ายรูปโดยตรงจากกล้อง Surveillance ที่ติดตั้งจริง
  ผ่านฟีเจอร์ Capture ในระบบ
  → รูปที่ได้มีสภาพแสง มุม และระยะเดียวกับที่ใช้ตรวจจับจริง
  → ค่า confidence เพิ่มขึ้นชัดเจน (0.63-0.79)

================================================================================
ส่วนที่ 3 — กระบวนการเก็บข้อมูล (Enrollment Process)
================================================================================

ระบบมี Pose Guide ช่วยให้เก็บข้อมูลได้ถูกต้อง

ขั้นตอน:
  1. เปิดหน้า Personnel Management บนเว็บ
  2. เพิ่มสมาชิกใหม่ กรอกชื่อและข้อมูล
  3. เลือกกล้อง (攝影機 2 หรือ 攝影機 3) สำหรับถ่าย
  4. ระบบแสดง Live Preview พร้อม Pose Guide

     ระบบวิเคราะห์ใบหน้า Real-time:
     - ตรวจสอบว่าใบหน้าอยู่ในตำแหน่งที่ถูกต้องหรือไม่
     - แสดงคำแนะนำ: "กรุณาขยับซ้าย", "ใกล้เกินไป" ฯลฯ
     - ปุ่มถ่ายจะ Unlock เมื่อตำแหน่งพร้อม

  5. ถ่ายครบ 5 ท่า ระบบแสดง Progress Bar
  6. บันทึก → รูปถูกส่งขึ้น Server และบันทึกลง faces_db/
  7. ระบบ Rebuild Embedding อัตโนมัติทันที

================================================================================
ส่วนที่ 4 — วิธีที่ระบบใช้ข้อมูลที่เก็บ
================================================================================

เมื่อได้รูปภาพแล้ว ระบบแปลงเป็น Embedding Vector ดังนี้:

  รูปภาพ (JPG)
       ↓
  InsightFace ตรวจจับใบหน้าในรูป
       ↓
  แปลงเป็น Embedding Vector ขนาด 512 มิติ
  (ตัวเลข 512 ค่าที่แทน "ลักษณะเฉพาะ" ของใบหน้า)
       ↓
  คำนวณ Mean Vector จากทุกรูปของแต่ละคน
  (เฉลี่ย embedding ทั้ง 5 ท่า = 1 vector ที่ครอบคลุม)
       ↓
  เก็บใน RAM พร้อมใช้งาน Real-time

  ตัวอย่างผลลัพธ์:
  Tongen  → embedding [0.12, -0.08, 0.34, ...] 512 ค่า
  jiabao  → embedding [0.45, 0.23, -0.11, ...] 512 ค่า
  TT      → embedding [-0.07, 0.61, 0.28, ...] 512 ค่า

  เมื่อกล้องเห็นคนใหม่:
  → แปลงใบหน้าเป็น embedding
  → คำนวณ cosine distance กับทุกคนในฐานข้อมูล
  → คนที่ distance ต่ำที่สุด = คนที่ระบบ "คิดว่าเป็น"
  → ถ้า distance ต่ำกว่า threshold → identify สำเร็จ
  → ถ้า distance สูงกว่า threshold → UNKNOWN (คนแปลกหน้า)

ส่วนที่ 5 — ปริมาณข้อมูลและคุณภาพ
================================================================================

  จำนวนข้อมูลที่เก็บ:
  สมาชิก 3 คน × 5 ท่า × 2 กล้อง = 30 รูป
  → สร้าง embedding รวม 14 vectors (บางรูปตรวจใบหน้าไม่เจอ)

  ทำไมไม่เก็บเยอะกว่านี้:
  ArcFace เป็นโมเดลที่มีความสามารถสูง
  แม้รูปน้อย แต่ถ้ารูปมีคุณภาพและหลากมุม → ผลดีกว่ารูปเยอะแต่ซ้ำมุม

  เกณฑ์คุณภาพที่ระบบตรวจสอบอัตโนมัติ:
  - ใบหน้าต้องมีขนาด ≥ 18 pixels (ไม่เล็กเกินไป)
  - ค่าความคมชัด (det_score) ≥ 0.35
  - ถ้าผ่านเกณฑ์ → นำไปสร้าง embedding
  - ถ้าไม่ผ่าน → ข้ามรูปนั้น แจ้งเตือนให้ถ่ายใหม่

================================================================================
สรุป
================================================================================

การเก็บข้อมูลในโปรเจกต์นี้ไม่ใช่แค่ "ถ่ายรูปให้ครบ"
แต่ต้องเก็บข้อมูลที่ "ตรงกับสภาพแวดล้อมการใช้งานจริง"

  หลักการสำคัญ:
  → ถ่ายจากกล้องที่ใช้งานจริง ไม่ใช่กล้องโทรศัพท์
  → ครอบคลุมหลายมุม เพื่อรับมือกับสถานการณ์จริง
  → คุณภาพของข้อมูลสำคัญกว่าปริมาณ
