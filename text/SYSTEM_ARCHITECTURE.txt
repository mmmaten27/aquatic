1. ภาพรวมระบบ (System Overview)
================================================================================

ระบบนี้เป็น Access Control System สำหรับห้องปฏิบัติการ (IoT Lab Aquaponics)
โดยใช้กล้อง 4 ตัวในการตรวจจับใบหน้า + YOLO สำหรับตรวจจับบุคคล เพื่อควบคุม
การเข้า-ออกห้อง โดยมีบัญชีพนักงานที่授权ไว้และระบบแจ้งเตือนผ่าน Telegram.

กล้อง 4 ตัว:
  - YOLO CAM (index 0): กล้องมุมกว้างกลางห้อง, ตรวจจับบุคคล/นับจำนวน
  - CAM1 (index 1): กล้องหน้าประตูทางเข้า (Entrance Door)
  - CAM2 (index 2): กล้องด้านข้างในห้อง มองเห็นใบหน้าชัด (Primary Face Cam)
  - CAM3 (index 3): กล้องทางออก (Exit Door)

เทคโนโลยีที่ใช้:
  - Backend: Python Flask (REST API)
  - Face Recognition: InsightFace (ArcFace buffalo_l)
  - Person Detection: YOLOv8 (Ultralytics)
  - Database: MySQL (pymysql)
  - Notification: Telegram Bot
  - Frontend: HTML + JavaScript (vanilla, fetch API)
  - Computer Vision: OpenCV

3.2 กล้อง (Camera System)
--------------------------------------------------
Camera Index Mapping:
  - YOLO CAM  → dynamic index (default 0)
  - CAM1      → dynamic index (default 1)
  - CAM2      → dynamic index (default 2)
  - CAM3      → dynamic index (default 3)

ฟังก์ชัน refresh_camera_indices() เรียกใช้ get_calibrated_indices()
เพื่อ map logical ID → physical index (รองรับ USB re-enumeration).

Capture Loop (surv_capture_loop):
  - อ่านเฟรมจากกล้องที่ 5 fps
  - แปลงเป็น JPEG (quality 50) และเก็บใน surv_frames[cam_id]
  - เก็บ raw frame ใน latest_raw_frames[cam_id] สำหรับ event capture
  - Retry mechanism: 8 fails → reconnect camera

YOLO Capture Loop (yolo_capture_loop):
  - อ่านเฟรมที่ 10 fps
  - ใช้ Motion Detection เพื่อลด YOLO calls:
        ถ้า pixel change < 1500 → ข้าม YOLO
        บังคับ run ทุก 30 วินาที (MOTION_FORCED_INTERVAL)
  - เรียก model.track() ทุก 3 เฟรม (classes=[0] = person only)
  - ส่ง face recognition request ทุก 15 เฟรม (detect_every * 5)

3.3 YOLO Person Detection
--------------------------------------------------
YOLO CAM ใช้ model.track() พร้อม persist=True เพื่อ track id
ข้ามเฟรม (BoT-SORT tracker ของ Ultralytics).

  Flow:
  1. อ่านเฟรม → motion gate check
  2. ถ้ามี motion → model.track(img, classes=[0], persist=True)
  3. กรอง detection ด้วย MIN_CONFIDENCE (0.70)
  4. ส่ง crops ไปยัง face_recognition_loop
  5. วาด bounding boxes + labels
  6. บันทึก detection_logs ใน DB
  7. อัปเดต current_person_count, daily_detection_total

Face Recognition Loop (face_recognition_loop):
  - รอ face_pending_event (Event flag)
  - เมื่อมี crop จาก YOLO → crop head region → recognize_face()
  - จัดการ per-track buffer: เก็บ crop ไว้ TRACK_BUFFER_SIZE=3
  - Retry ด้วย buffered crops ถ้าเฟรมแรกไม่ชัด
  - ถ้าเจอ → update_sighting() และ update_occupancy_last_seen()
  - ถ้าไม่เจอ → track_first_seen รอ UNKNOWN_DEFER_SEC=15s → alert

3.4 Face Recognition Pipeline
--------------------------------------------------
Face recognition ใช้ InsightFace ArcFace (buffalo_l model)
generate embedding 128-dim → cosine distance กับ embeddings ใน DB.

  Pipeline (ใน recognize_face() ที่ face_utils.py):

    1. Lighting Normalization (CLAHE)
    2. Face Detection (InsightFace detector)
    3. Quality Gate (det_score >= profile.quality)
       CAM_PROFILE:
         cam0: quality=0.40, sim_thresh=0.55
         cam1: quality=0.40, sim_thresh=0.55  ← entrance
         cam2: quality=0.42, sim_thresh=0.50  ← primary face
         cam3: quality=0.38, sim_thresh=0.55  ← exit
    4. Size Gate (face width/height >= min_size)
       ถ้า < SOFT_SIZE_THRESHOLD(50px) → size_penalty
       size_penalty = (1 - ratio) * size_penalty_coeff
         cam1: coeff=0.04 (เบากว่า ปรับมาแล้ว)
         อื่น: coeff=0.08
    5. Embedding Extraction → cosine distance
         best_dist = 1 - dot(emb, db_emb)
    6. Threshold Check:
         best_dist < sim_thresh + size_penalty → match
    7. Inter-Class Margin Check:
         margin = second_dist - best_dist
         ถ้า margin < MIN_INTERCLASS_MARGIN(0.08) → AMBIGUOUS → reject
         ข้อยกเว้น: best_dist < HIGH_CONF_THRESHOLD(0.35) หรือ
                    best_folder == second_folder → skip margin check

  Return value format:
    สำเร็จ: {"name": "Tongen", "status": "authorized", "confidence": 0.51}
    ไม่สำเร็จ: {"name": None, "status": "unknown", "confidence": 0.0,
                "candidate": "Std001", "candidate_confidence": 0.49,
                "ambiguous_with": "std002"}  ← แก้ไขแล้วให้มี candidate

3.5 State Machine (Unified Access Control)
--------------------------------------------------
ทำงานใน unified_state_machine() thread ทุก 1 วินาที.

  ตัวแปรสถานะ:
    person_state = {
      face_folder: {
        "name": "Tongen",
        "inside": True/False,
        "entered_at": datetime,
        "entered_at_timestamp": timestamp,
        "last_seen": {1: ts, 2: ts, 3: ts, 'yolo': ts},
        "last_confidence": {1: conf, 2: conf, 3: conf, 'yolo': conf},
        "exit_pending": True/False,
        "exit_started_at": timestamp,
      }
    }

  ENTER Logic (inside=False → inside=True):
    เงื่อนไข (ต้องการอย่างน้อย 1 ข้อ):
      • cam1_solo  = cam1 มองเห็น + confidence >= 0.40
      • cam2_solo  = cam2 มองเห็น + confidence >= CAM2_SOLO_CONFIDENCE (0.50)
      • cross_conf = cam1 AND cam2 มองเห็นพร้อมกัน

    Time windows:
      cam1 ต้องเห็นภายใน ENTRY_WINDOW_SEC (12s)
      cam2 ต้องเห็นภายใน ENTRY_WINDOW_SEC (12s)

    เมื่อ ENTER:
      1. state.inside = True
      2. record_entry(name) → เพิ่มใน room_occupants
      3. _save_event_capture("ENTER")
      4. _do_notify_enter(name) → Telegram (ถ้าอยู่นอกเวลางาน)

  EXIT Logic (inside=True → inside=False):
    2-Stage Process:
      Stage 1: cam3 เห็นคน → state.exit_pending = True
      Stage 2: รอ EXIT_CONFIRM_DELAY_SEC (8s)
        - ถ้าไม่มีกล้องไหนเห็นคนอีก → CONFIRM EXIT
        - ถ้ายังมีกล้องเห็น → CANCEL EXIT
        - ถ้าเกิน EXIT_MAX_WAIT_SEC (30s) → FORCE EXIT
      Grace Period: ถ้า enter < 30s → ignore exit trigger

  Multi-Frame Voting (CAM1) (เพิ่มใหม่):
    ถ้า CAM1 reject ใบหน้าด้วย ambiguous margin แต่เจอ candidate เดิมซ้ำ
      3 เฟรมติดต่อกัน → force accept (bypass ambiguous check)

  Stale Occupant Cleanup:
    - ถ้าคนในห้องไม่ถูก detect ด้วยกล้องตัวไหนเลย
      นานเกิน STALE_OCCUPANT_SEC (300s) → ถือว่าออกไปแล้ว

เส้นทาง ENTER (คนเข้าห้อง):

  CAM1 (Entrance)                     CAM2 (Indoor Face)
       │                                    │
       ▼                                    ▼
  YOLO detect คน                    YOLO detect คน
       │                                    │
       ▼                                    ▼
  Face Recognition                   Face Recognition

       │                                    │
       ▼                                    ▼
  surv_detect_loop(1)                surv_detect_loop(2)
  │                                     │
  │  ถ้า ambiguous →                    │  identify ได้ →
  │  vote 3 เฟรม → force accept         │  update_sighting(name, 2, conf)
  │                                     │
  ▼                                     ▼
  update_sighting(name, 1, conf)    update_sighting(name, 2, conf)
       │                                    │
       └──────────┬─────────────────────────┘
                  ▼
        unified_state_machine()
                  │
        เช็ค cam1_solo / cam2_solo / cross
                  │
        (ด้วย CAM2_SOLO_CONFIDENCE=0.50)
                  │
                  ▼
           inside = True
                  │
                  ▼
       record_entry(name)
       _save_event_capture("ENTER")
       _do_notify_enter(name)

เส้นทาง EXIT (คนออกจากห้อง):

  CAM3 (Exit)
       │
       ▼
  surv_detect_loop(3)
       │
       ▼
  YOLO proxy → infer occupant
       │
       ▼
  update_sighting(name, 3)
       │
       ▼

       │
       ├─ Stage 1: exit_pending = True
       ├─ Stage 2: รอ 8s
       │     ├─ ไม่มีกล้องเห็น → EXIT
       │     ├─ ยังมีกล้องเห็น → CANCEL
       │     └─ เกิน 30s → FORCE EXIT
       │
       ▼
  record_exit(name)
  _save_event_capture("EXIT")
  _do_notify_exit(name)
